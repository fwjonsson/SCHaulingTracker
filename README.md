# Hauling Tracker

Reads Star Citizen `Game.log` files and fills in your hauling session sheet.
Only **Station to Ruin** hauling contracts are used. Ruin to Station missions are ignored.

## Build and run

You need the .NET 10 SDK (Windows).

    cd HaulingTracker
    dotnet run

or open `HaulingTracker.csproj` in Visual Studio and press F5.
To make a single exe: `dotnet publish -c Release -r win-x64 --self-contained false`.

## Updates

The exe from the [Releases page](https://github.com/fwjonsson/SCHaulingTracker/releases/tag/latest) (the "latest" release the build makes from `main`) updates itself. At startup it asks GitHub for the newest build; if there is a newer one it asks **Update now?** (default No). On Yes it downloads the new exe, renames the running one to `HaulingTracker.old.exe` (kept as a backup until the next update), puts the new one in its place and restarts. Your data is not touched. **Options → Check for Updates…** does the same by hand and always answers. The version (the first letters of the commit) is at the bottom of the Options menu.
A program you built yourself (Visual Studio, `dotnet run`) has no build version, so it never updates itself. A build from a branch that is not merged yet is never replaced by an older one. If the exe sits in a folder that needs administrator rights (like Program Files) the update fails with a message and nothing changes.

## Use

1. **Options → Open Log File(s)…** to read old logs (pick several at once, for example logs split by a crash).
   Or **Options → Watch Live Game.log** while you play. The window updates every 1.5 seconds. The top bar shows the time of the last line read from the logs (*last log line 04:36:12*): if it keeps moving the program is following the game. The window also reads the logs and repaints when you come back to it. A cell that was left in edit mode on another tab no longer stops the updates.
2. Press **Start Session** on the front page to begin a session (and **Stop Session** to end it). The drop-down lists your sessions (both are in the top row of the window, on the right, level with the Options menu; the status text is just right of Options). Missions outside every session are not shown. A contract that is still active in the game is shown in the running session even if you accepted it before you pressed Start (so you can stop and start a session without losing it); runs that were handed in before the session started are not shown in it.
3. Start and End times are filled from the log. Type over them if you want. **Use log times** resets them.
4. Rename each pickup location once (click the name). It is remembered for every future session.
5. Pick the worker for each location, write notes. Payouts can be changed in the reward table.
6. **Copy table for Google Sheets** copies the pickup table, ready to paste into the sheet.

Your data is saved in `%AppData%\HaulingTracker\data.json`. The first time the program starts each day it also keeps a dated copy (`data-2026-10-20.json`) in a `Backups` folder next to it, the newest 30 days (**Options → Open Backup Folder**). To go back, close the program and copy a backup over `data.json`. On the Debts tab, **Data File…** moves it to another folder, for example in OneDrive, so it follows you between PCs. Run the tracker on only one PC at a time then, because it rewrites the whole file on every change.

## What the log can and cannot tell

- Several missions with the same pickup are grouped into one row with a count.
- **From Ruin** (right of the location name) is the distance in Gm from Ruin Station to that pickup, taken from the Pyro distance table. It stays empty for a location the table does not know.
- The pickup table only shows missions that are not completed yet. While you still have open missions, completed ones are gone from it, so after you finish a batch of contracts and accept new ones you only see the new ones. When everything is completed and you have not accepted anything new, the finished locations stay on the table until you start adding new missions. Nothing else forgets them: the run board, both leaderboards, the totals (Batches Delivered, Missions Completed, aUEC) and **Copy table for Google Sheets** still cover the whole session. The worker and notes you typed for a location are kept and come back if the location shows up again.
- The Missions column shows missions still waiting / missions with cargo at that location, so 5 missions start as 5/5 and count down as you load. Yellow = partly loaded, green = all loaded.
  The log has no SCU numbers, so it only knows loaded, partly loaded or not loaded.
- Loaded and delivered times are shown on the run board. "Copy table for Google Sheets" still fills them in per location.
- If the log misses a final "completed" push, stops of a finished mission count as loaded.
- Not in the log: location names, SCU per location, rewards. These are typed by you.

## Runs, players and two computers

- The lower table lists every run. A run ends at each hand-in at Ruin, also a partial one.
- Rewards: completed 2, 3 and 4 stop contracts are counted from the log. Type the payout of each type and the totals, revenue and hourly rate calculate.
  Hand-ins less than 3 minutes apart count as one hand-in. Run #1 starts at the first accepted contract.
- Each Game.log belongs to one player (the character name in the log). The run board shows the runs of all loaded players side by side, the top table follows the player picked in the drop-down.
- **Options → Add Live Source…** adds the StarCitizen folder (the one holding LIVE and HOTFIX), also on another computer through a shared folder (UNC path). **Log Channel** in the same menu picks LIVE, HOTFIX or Auto (the log written most recently). All added sources are watched at once.
- When watching starts (and when the game starts a new Game.log) the logs in the `logbackups` folder that are less than 24 hours old are read first, so a session that was already going on, for example before a crash, continues.
- **Options → Sources…** lists every added live source, shows if it can be reached right now, and lets you remove one. Untick **Enabled** to switch a source off without losing its address; tick it again to use it later. A switched-off source is not read at all. A tick works at once, you do not have to close the window, and ticking a source again after all were off starts watching again.
- Mission updates reach the whole party, so the logs of all accounts are merged and a shared mission counts once.
- **Options → Party…** opens a table where you type names and tick **Active**. The active names are the crew of the Trip Planner. When someone is unticked (or removed), the run he has on the way ends at that moment: it shows **left** in the Missions / Batches column and is not marked failed, so a run that never got a hand-in no longer stays open for ever. Missions of his that were completed still count as carried.
- **Station names** are found by the position of the station in the log, not by its id, because the id is different on every server. So the stations keep their names from one day and one server to the next. The Nyx and Stanton Gateways have the same position, so they are told apart by their ids (Nyx has the lower one of the two; with only one of them seen, it stays unknown). Clicking into a name cell and leaving it again no longer saves the name as one you typed; a saved name that is just another station's name is ignored when the station is known. The long names are shortened (Megumi, Dudley, Rod's Fuel, Starlight, Nyx GW, Stanton GW), also where an earlier version saved the long name. A station that is not in the table shows as `Unknown ...id`; you can type a name for it in the board.
- When all your missions are completed and you then accept new ones, the locked Current trips of the Trip Planner are cleared (a clean slate for the new set). The old runs keep their workers and the leaderboards do not change. Notes stay. (The old **Assigned Worker** column is gone from the Stops table; sessions from before it was removed keep what was assigned in them.)
- A location nobody is assigned to is assigned automatically to the player the logs show picking up there. You can change it, and bildog123 (no log) has to be assigned by hand.
- The run board makes runs per worker. **There is no Assigned Worker any more**: the worker of a pickup is the player the logs show taking the cargo out of the freight elevator (needs that account's log); if no log shows it, the credit the Trip Planner decided and saved when the batch was picked up (the worker whose locked stop it was, then the worker whose planned trip needed a batch there, in the order of the plan, and otherwise the only member without a log), which never changes again, also not when the program restarts or updates; and only if there is none, the player who handed that mission in. Nobody is credited with more batches than his ship holds. Only runs get credit, a run is from a worker's first pickup to his hand-in. Pickups from before this change keep the old rule. The finished stops show who carried from them.
- A run is leaving the base, collecting cargo from any number of missions and handing it in at Ruin. A hand-in ends only the run of the player who did it, never somebody else's run, whatever missions it was for. Who did it is read from the logs (the loading platform lines). If no log names anybody, it is credited to a worker without a log (like bildog123).
- Any pickup signal counts a stop as picked up. If you had to leave cargo, write it in Notes.
- **Column widths.** On the Session tab the first columns of the Stops, Finished Stops and Cargo Runs boards are as wide as the matching columns of the Session Leaderboard (#, Worker, Completed Runs, ...), so they line up; Notes (and Handed In) take what is left. The web page does the same. There the Party, Contracts and Session tables also use four equal columns (the two columns of Session are two of them, so the middle line is straight), and a party member's whole row has his colour instead of a colour column. The side with them is a narrow column (as in the program), so Stops and Finished Stops get the width, and the Notes column.
- **Cargo Missing.** When a mission has a pickup signal at every stop, something was handed in after the last pickup, nobody is still flying cargo of it and the hand-in is more than 5 minutes old, but the game does not complete the mission, some cargo is gone (a lost or forgotten box, for example). The mission is marked **Cargo Missing**: its stops in Finished Stops say *Cargo Missing* (in orange) instead of the hand-in time, and Active Missions says how many are missing. The log does not say which stop or trip lost the box, only that the mission is short. A mission with missing cargo no longer keeps the session clock running and does not hold up the clean slate for the next set of missions. If the cargo turns up and the mission completes, the marker goes away by itself.
- The reward table counts every accepted contract: **2 / 3 / 4 To Ruin** (the hauling missions with 2, 3 or 4 pickups) and **2 / 3 / 4 From Ruin** (the from-Ruin contracts, by their number of drop-offs). Payouts start at 1,268,250 (2 stops), 1,691,000 (3 stops) and 2,113,750 (4 stops, Master rank), the same for To Ruin and From Ruin (the log never says what a contract pays); type another number to change one, and an empty or 0 cell goes back to the built-in payout. The From Ruin payouts give the from-Ruin loads their value: a drop-off is worth the reward / drop-offs of its contract, on the Ruin line where the load is collected in the Current Route, in the trip totals, in the Value of Cargo Runs (with the waste the run delivered), in Total aUEC Earned (contracts that are done) and in the session revenue. The Debts tab still only counts the pickups.

- **Value** on the upper board is what the missions at that location are worth: every mission pays its reward split over its stops (reward / 2 for a 2 stop mission, reward / 3 for a 3 stop mission, reward / 4 for a 4 stop mission), times the stops at that location. It follows the payouts in the reward table.

## Runs, lost cargo and history

- **Lost Cargo** on a run is a drop-down: None, Little or All (All also marks the run as failed, see below). A run row is yellow while the run is on the way, green when it is completed with everything delivered, orange for Little lost and red for All lost.
- **Completed** is the time the run ended, at the hand-in at Ruin Station. It stays empty while the run is on the way. **Missions** is how many missions were handed in then. **Pickup Location & Time** lists where the run went and when: the pickups (*Rod's Fuel 15:36*) and the waste of a from-Ruin contract that was taken out at Ruin (*Waste from Ruin 13:19*) and delivered to a station (*Waste → Rat's Nest 15:55*), in the order it happened. A run also starts when a worker leaves Ruin with waste: delivering it is a run on the way before anything is picked up. Who took the waste out and who delivered it comes from the logs (only the player who does it has the freight elevator and loading platform lines), so a mission that was shared with someone is only counted for the one who delivered the load, and a step that no log shows is not counted. The time columns sit together after Missions: **Started**, **Completed** and **Time** (the run time, with seconds). A run starts at the previous hand-in. The first run starts when the first mission of the batch was accepted (whichever order the trips are flown in), and when everything was handed in and new missions are accepted, the clock starts again with that acceptance, so a break is not run time. For a run that is on the way, Time counts up from Started while you watch live. The **Total** row's Time is the time of the whole set of missions: it counts from the moment the first mission of the set was accepted (the finished runs are no longer listed in the table, so it cannot be added up from the rows) and stops when everything is handed in. **Flight time** (right after Time) is the estimated flying time of the run: Ruin, the stations it went to (waste delivered, pickups) in the order of the visits, and back to Ruin, with the worker's quantum drive. It is the same estimate as the Flight time of the Trip Planner, so you can compare it with the Time.
- **Lost Cargo** is a drop-down: None, Little or All. **All** marks the run as failed: a run still on the way ends there, it does not count as a run, and its value is shown as lost. Pick None or Little again to bring it back.
- **History tab:** every session is saved with its date, missions, revenue and what each worker carried, so earlier sessions stay after their logs are gone.

## Layout

Every board has a title. At the top: the pickup board (**Stops**, and, when there are some, the **Finished Stops**) on the left, and on the right the party table with its entry row (**New member**, **Add**, **Remove**) right under the last member, and under it the small **Contracts** table and the clean **Session** table (times, missions, revenue, hourly rate). The party table is as high as its members (it scrolls after six). Under them the **Session Leaderboard** runs over the full width. **Cargo Runs** takes what is left of the window and scrolls, with the run that had the latest activity on top: a run that gets completed (handed in) jumps to the top, a run still on the way sits by its last pickup. Not sorted by run number. The pickup board and the leaderboard are always shown in full. The Stops, Finished Stops and Session Leaderboard tables have a **#** column at the far left that counts the rows (1, 2, 3...), also on the web page, so you can see at a glance how many stops there are. In **Cargo Runs** the run number is that **#** column, also at the far left. The tabs are Session, Trip Planner, Debts and History, in the same order and with the same layout in the live web view (the web page has the same titles: Stops, Finished Stops, Party, Contracts, Session).

The program starts watching the logs by itself when it opens, and reads the backup logs of the last 24 hours first.

## Dark mode

**Options → Dark Mode** switches between the light and the dark look. The choice is saved in the data file and used the next time the program starts. The dark look covers all tabs, tables, buttons, dialogs and the title bar (Windows 10 or later).

## Trip Planner


**From-Ruin contracts (alpha).** The "Single to Multi" contracts (cargo is loaded at Ruin and dropped off at 2 to 4 stations) are recognised from the log. All of them are waste, and the waste of different missions looks the same, so the plan is one such contract per account at a time. Every drop-off objective that is not completed yet counts as one batch for now (the log has not shown what happens when one is delivered, so this is the part to check). The **Stops** board has a **Drop-off** column (gold) with what has to be brought out to every station (*Waste ×1*); a station that only has drop-offs gets a row of its own. **The pickups come first**: the planner works out the trips for the pickups (to Ruin) on their own, and the waste only rides along on those trips. A trip leaves Ruin with the load of one mission for its **first stop**, unloads it there (a ship never carries outgoing and incoming cargo at the same time) and then picks up. **A load never adds a stop**: it only rides along on a pickup trip that picks up at its station anyway (the landings are what costs the time, and unloading and loading at the same station saves one); that station becomes the trip's first stop, and among such trips the load goes where it adds the least flying (the Queued routes table says *Ruin → Rod's Fuel → Endgame → Ruin*: the load is collected at Ruin, the drop station comes first and the rest of the trip is the cheapest way from there; the Current Route table says what is done at every stop: *Collect Waste* at Ruin (Cargo: *152 SCU: 4×32 + 24*), *Drop Waste | Collect ×2* at Rod's Fuel, *Collect* (Cargo: *1 Batch*) at Endgame and *Drop* (*3 Batches*) at Ruin). Drops at two stations go in different trips, every trip takes at most one load, and the trips with a load come first in the list of a worker, so he is rid of his cargo as soon as possible and can take the next from-Ruin contract. **A trip only to drop off waste is the last resort**: a worker only gets one when he has nothing at all to pick up and no run in progress. A load that no pickup trip can take along (no trip picks up at its station, every such trip has a load already, or nobody who has that mission has one) waits until one can (it does not show in the planner: the line above the map is gone, to give the tables more room). After a drop-off the worker's next trip starts at that station (he cannot pick up more waste there): the planner counts his flight home either way, so it fills that flight with pickups on the way instead of sending him back to Ruin first; and when his next trip does have to start at Ruin, his Current Route begins with the station where he is, so the flight back to Ruin is in the distance and time. A worker only gets the load of a mission he has (the Contracts tab decides who has what), and a worker who is flying a run does not get a load. The game tells how many SCU every drop-off is (the "Deliver 0/147 SCU of Waste" popup), and the program shows it with the containers to load, as big as possible (sizes 32, 24, 16, 8, 4, 2 and 1): 147 SCU is *147 SCU: 4×32 + 16 + 2 + 1*. It is in the Drop-off column and in the Cargo column of the Current Route table, only on the Ruin line where the load is collected (not again where it is dropped) (*147 SCU: 4×32 + 16 + 2 + 1*). The game does not always write that popup when you accept (it can come an hour later, or not at all): then the Cargo cell says *? SCU (click to type)*. Click it, type the SCU from the contract, and the program works out the containers and remembers it (saved with your data); the game's own number wins once it writes it, and 0 clears what you typed. A load is only given to a worker whose **Ship** (Party table) holds that many SCU, with the room off grid of the C2 (+128) and the Hermes (+168). The from-Ruin contracts are on the **Contracts** tab too (Contract *From Ruin, 3 drop-offs*, Cargo *Waste*, and the drop-offs with their SCU and a ✓ when delivered): the boxes there decide who can take a load (the planner only gives a load to someone who has the mission), and **Gone** takes a contract out of the plan. Not done yet: they are not on the web page. Their payout is what you type in the From Ruin rows of the reward table (see above).

**Contracts tab.** Between Trip Planner and Debts: every mission that is still going, from the oldest down, with its Contract (the number of stops), the Cargo, its **Pickups** (the stops it has, a ✓ behind the ones that are picked up, so you can match a row with a mission in your game) and one box per party member. A green ✔ means the member has the mission (it was shared with him), a red ✖ that he has not; click a box to change it. The member who took the contract has a gold box, which can be changed like the others (he may have lost the mission while the others still have it). The logs tell the program who has what: a member with a log has a mission when his own log has it (a mission that one account abandoned or never got is a red ✖ there, until it is shared with that account again: then it is accepted again in his log and the box turns green); a member without a log (bileh123) shows a green ✔ while he is active in the party, unless the others were told that he left the mission (an inactive member is a red ✖ unless the game told that he joined it), and the game also tells when somebody joins a mission (shared with him), so a share is seen when it is made. The taker is the account whose log shows the contract accepted first, so a contract that a member without a log took and shared shows the first account that got it as the taker. Click a box and the choice is kept (it wins over the logs until it is the same as what the logs say). A mission that is not in the game any more, but that the logs never ended (the game sometimes drops a mission without saying so, so the app still waits for a batch that is not there), has a **Gone** button at the end of its row: the mission then counts as abandoned everywhere (the Trip Planner stops planning its batch, the Session tab and the payouts forget it) and its row turns grey with **Bring back** to count it again. The Trip Planner only plans a worker for batches of missions he has (if one of the three batches at Rat's Nest belongs to a mission only zzatvo has, zzoega is planned for the other two, and the note above the tables says which batches only some of the crew can take). The Mission Payouts of the Debts tab are shared between the members who have the mission (a mission that already has its payout kept keeps its members, so earlier sessions do not change); if nobody has a green ✔, the active members share it as before.

**Distances and flying time.** The distances between the Pyro stations are calculated from the real positions of the stations in the game data (they match the distances you read in the game within 0.1 Gm). Pick each worker's **QT Drive** in the Party table (all 57 drives of the game data) and the planner estimates the flying time of every jump like the star map does: the drive speeds up with its stage 1 acceleration until the engage speed, then with its stage 2 acceleration up to the top speed, flies at the top speed and slows down the same way (a short jump never reaches the top speed). The spool time is not part of the time. The planner plans so the crew finishes at about the same time (a worker with a faster drive gets more of the flying). **The ships are filled by SCU, not by batch count.** A batch is about the SCU of its mission divided by its stops (the "Deliver 0/N SCU" popup; when the game has not written it, a mission counts as 500 SCU), so a batch of a 2 stop mission is about 250 SCU and one of a 4 stop mission about 125. Every ship holds what its **Ship** in the Party table holds (a C2: 696 SCU on the grid plus 4 × 32 SCU off grid = 824 SCU; no ship set: its batches times 232 SCU). The Cargo column of the Current Route says it for every stop and for the hand-in: *3 Batches (~375 SCU)*. Every stop also counts as 4 minutes of landing, loading and take-off when the planner compares plans (not in the times shown), so it prefers fewer stops: a station with a full ship of batches becomes a one-stop trip, and a stop is only split over several trips when that really saves flying. Every row of the Trip Planner tables has an **In flight** time (the last column; it is called **Flight time** in Cargo Runs): the estimate for that whole route (Ruin, the stops, back to Ruin) with the drive of its worker, also for a run; in the Current Route table every line has the time of the leg that leads to it, so they add up to the Total. How long a run really took is the **Time** of Cargo Runs. The drive is no longer written in the title of a table (only a note when none is set). Loading time is not included. Without a drive set, an Odyssey (S2) is assumed. The calculation was checked against SPViewer with a TS-2 (S3, 12 jumps from 1 to 150 Gm, all within 2 seconds) and an XL-1 (S2) and a VK-00 (S1) (1, 15 and 100 Gm, all within 1 second); the other drives of those sizes use the same formula. Size 4 drives (Allegro, Mauler) are only approximate: an Allegro is up to 10 seconds off.
The **Trip Planner** tab divides the open batches over the whole crew, so everybody flies as little as possible and you finish at about the same time.
- The crew is the active party. In **Options → Party…** tick **Active** for who flies and type each member's **Batch Capacity**: how many batches his ship holds per trip (for example 3 for a C2 and 2 for a smaller ship). It is saved per member.
- The plan is free (**Next Stops: Unlocked**) until you press the **Next Stops** button, see below. The plan also follows the batches you pick up while you play. The program shows one page with everybody (no tabs): a square **map of Pyro** on the left, in a frame with the team status line (like on the web page), with a short, read-only copy of **Cargo Runs** under it, and the tables of everybody on the right. The tables of the workers go down the whole right side, so there is room for more workers, and the page only scrolls when they do not fit. The map is always a square (its size comes from the size of the window only, so it keeps its size when the plan is updated). The **Next Stops: Unlocked / Locked** button is in the top bar of the window, level with Options and Stop Session, while the Trip Planner tab is shown; hold the mouse over it for the explanation. There is no title and no summary line. The web page shows the same single page. Only a warning (stations that are not in the distance table) is shown under the summary. On the map every planned trip is a line from Ruin through the stops and back (arrows show the direction); every worker has his own colour, his current trip is a bold line and the later trips are dotted, also on the web page. Each worker has two tables, the **Current Route** and the **Queued routes** (see below), and in the Current Route the worker's colour is on the step he is doing: the stop where he is still busy (*Collecting*), and once that is done (*Collected ✓* (*2 Batches*), or *Delivered Waste ✓* as soon as the waste is sent down the elevator) the next stop, the one he is on his way to. The short copy of **Cargo Runs** under the map has only the **#**, the **Worker** and the **Locations** (the places of the run in order, like *Ruin, Gaslight, Dudley*, without times) and keeps the runs in view while you plan; the Session tab has the whole, detailed table. The web page has the same layout (the map in its frame with the short Cargo Runs under it, the tables on the right); there all tables have the same narrow columns and a long Route column.

- **Locked stops and runs in progress.** **Next Stops: Unlocked / Locked.** Nothing is locked until you press this button, so the planner plans freely (also the first stop of everybody) and works the plan out again whenever something changes. Pressing it (it asks "are you sure" first, so you do not reshuffle by accident while people are on their way) works the plan out and locks the next stop of everybody to him and shows **Next Stops: Locked**; pressing it again (it asks too) unlocks everything. While it is on Locked, everybody who flies gets his next stop locked by itself: when a new set of missions begins, and again every time a worker hands in a run, the first stop of his trip is the one he is heading for, so it stays his when somebody else hands in a run and the plan is worked out again. Only the **next stop** of a worker is locked, and only while he is on his way to it (nothing is marked in the tables: the planner just keeps that stop for him). It locks the next stop of everybody: everybody at the start, everybody who has handed in a run and is heading for the next one, and everybody flying a run with room left (a worker whose next trip only has a drop-off from Ruin first has no pickup to lock). Planning again, or someone joining the party, never takes that stop away from him, but the rest of his trip is planned freely, so the planner can still put a better stop after it (for example 2 batches at Endgame instead of the stops it planned first). A worker who is flying a run (picked up, not handed in yet) has his cargo counted in his ship, and the **next stop** of the rest of his trip is locked too while there is room left (picked up at Gaslight, on the way to Endgame: Endgame is locked to him; with a full ship, or only the way back to Ruin left, nothing is). The run he is flying is his **Current Route**, and what the plan adds to it is part of that same table: the stops he has picked up, then the stops still to pick up (for example the lines *Checkmate* with *Collected ✓* (*1 Batch*), *Rod's Fuel* with *Collect* (Cargo: *2 Batches*) and *Ruin* with *Drop* (*3 Batches*): the ✓ marks what is already on board, and every line has the distance and the flying time of the leg that leads to it). On the map the line starts at his last pickup. So after one batch at Checkmate the plan gives him 2 more in the same table. The trips after that are his **Queued routes**, numbered 1, 2, 3, ... (the first column of that table is **#**: the number of the trip). When a locked stop has been picked up, the next one is locked, and when his run is handed in, the first stop of his next trip is locked. The lock ends when he picks up somewhere else, when its batches are picked up, and when he leaves the party (his batches go back to the others). A lock belongs to the session and is cleared when a new set of missions begins. Unlocking clears all locks, so everything can be reshuffled. The way home of a run in progress counts in the time of its worker even when nothing is added to it, so a stop close to where he is (one batch at Megumi after two at Stanton GW) is compared with flying straight home, and is added to the run when that is shorter for the crew. **Where he is flying keeps its batches**, locked or not: when a worker's own Game.log shows the quantum destination he has set (or arrived at) since his last pickup or delivery, the batches there that fit in his ship (and that are of missions he has) stay his next stop, so planning again for somebody else (someone hands in, drops off waste or accepts new missions) never takes them away while he is on his way there or about to bring the cargo up from the elevator. That needs his log; without it, only the Next Stops button keeps a stop.
- Each worker has two tables. The **Current Route** (on the left) is the run on the way or, when he has no run in progress, his first planned trip: one numbered line per stop, in flying order from Ruin back to Ruin (Ruin is the first and the last line). **Stops** is just the station, and **Drop/Collect** says what is done there: *Collect* (Cargo: *2 Batches*) (pick up the batches there), *Drop Waste* (unload a load from Ruin, see below) and, for the run you are flying, what is done already with a tick: *Collected Waste ✓* on the Ruin line (the waste taken out there in this run; the game completes every pickup of the contract at once however much you take, so there is no count, and the Cargo is that of the loads delivered since), *Delivered Waste ✓* where the waste was delivered (at once when it is sent down the elevator: nothing is left to do there) and *Collected ✓* (*1 Batch*) for the cargo on board. **Cargo** says how many batches are picked up or handed in there (*3 Batches*; the Drop/Collect column only says what is done), and for a load from Ruin the SCU first, then the containers to use, like *198 SCU: 6×32 + 4 + 2*. A load that goes out from Ruin has its SCU and the containers to use, as big as possible (the sizes are 32, 24, 16, 8, 4, 2 and 1), like *152 SCU: 4×32 + 24*: only on the Ruin line where it is collected (one such part for every drop-off if there are more of them; *? SCU* when the game never said how big the load is). The batches you pick up have no SCU or containers in the Cargo column: they all go to Ruin, so the number of batches at a stop (*Collect* (Cargo: *2 Batches*)) is all that is needed (the code that guesses it, *~5×32 + 2 + 1*, is still there, switched off by `ShowPickupScu`, for a later version) (the log only tells the SCU of a whole mission, *Deliver 0/490 SCU of Carbon*, so it would be an equal share per stop anyway). The lines that are done say the same as the lines that are planned. While a worker is still busy at the place where he is (he has pulled the cargo out of the elevator, but not selected his next quantum destination yet) the line says *Collecting* without the tick, and turns into *Collected ✓* (*2 Batches*) when he selects the next destination. That needs the Game.log of that worker (the game writes the quantum destination only in his own log); without it the tick comes at once, like before. Everything done in the run stays in the table, in the order it happened, until the run is handed in at Ruin; what the plan still adds comes after it, and Ruin is the last line. A trip with a load starts with the Ruin line *Collect Waste ×3* (Cargo: *152 SCU: 4×32 + 24*) (once he has brought the waste up from the elevator at Ruin it says *Collecting Waste* while he is still at it (the same words as the pickups: *Collect* planned, *Collecting* busy, *Collected ✓* done), and *Collected Waste ✓* once he has set his next quantum destination; his colour then moves on to the drop-off) and ends with the Ruin line *Drop* (*3 Batches*) (the batches handed in). The **Queued routes** (under the Current Route, as wide as it) are the trips after that, the one-stop trips first (after a trip that takes cargo out from Ruin): while you fly those, missions get completed and new ones come in, and the trips with more stops are planned again with the new missions, one line each, numbered 1, 2, 3, ..., with its **Route** (like *Ruin → Rod's Fuel → Endgame → Ruin*; the map draws them as dotted lines), how many **Stops** it has and its **Batches** (the total of that trip only); the Total line is marked Σ. Every worker's name (in capitals and in his colour), location and two tables sit in a frame of their own, so it is clear where one worker ends and the next begins. Both tables have the **Value** (a run: what its batches are worth, like in Cargo Runs; a planned trip: the batches at each stop times what an average batch at that stop is worth, reward / stops of its mission, from the rewards in the Session tab), the **Distance** in Gm and **In flight** (the estimated flying time). The tables are the same for every worker, so they line up, and a row is one line high unless the window is so narrow that a text has to wrap. A run that is finished is taken out of the tables as soon as it is handed in; the whole history stays in **Cargo Runs** below.
- **Total.** Both tables of a worker end with a **Total** line: the number of stops, the batches (*Collect* (Cargo: *3 Batches*) in the Current Route) with their SCU (*~392 SCU* under Cargo), the value, the distance and the flying time (In flight) of all the rows above it. The title above the tables of a worker is just his name.
- **Current location.** Every worker has a **Current location** drop-down right of his name (above his two tables): where he is now, and where the plan starts his next trip. It follows the logs by itself and then says *Automatic: Starlight* (the station): after a pickup he is at that station, after he delivers the load of a from-Ruin mission he is at that drop-off (only the worker whose own log shows him at the loading platform; when a mission is shared with him and somebody else delivers the load, he does not move), and after a hand-in (or before anything has happened) he is at Ruin Station. The line of the Current Route where he is has his colour (the station of his last pickup while he flies a run, the first line of a trip that has not started). A run in progress continues from his last pickup, and what is left at the station where he stands (that he has the missions for) is taken first, so he picks up right where he is before the plan sends him anywhere else (the Current Route then starts with the station he is at, and a queued trip starts with that station instead of Ruin). You can also set it by hand, for example for everybody at the start of a session, when someone sits at a station with an empty ship, or when something strange happens and the logs missed a pickup: pick the station in the drop-down and the box says *set by you*; the plan starts from there at once, also for a worker who is flying a run (it then continues the run from that station). Picking a station releases his locked next stop, so the plan is free to change. A choice by hand holds until the logs show him picking up, delivering a load from Ruin, handing in, taking waste out at Ruin or selecting a quantum destination (his own log) after that; from then on the box follows the logs again. Pick *Automatic* to give it back to the logs yourself (Ruin Station by hand is a choice too, for a worker who is back at Ruin after a delivery elsewhere). The drop-downs are only in the program; the web page shows the result in the title above the tables of every worker (*zzoega – Current location: Patch City*). If the plan ever cannot be worked out or shown, the program says so above the tables (and tries again on the next update) instead of leaving an old or empty page.
- The map is drawn on black with the orbit rings of Pyro I, Monox, Bloom, Pyro V and Terminus, the planets and the sun (same in the live web view). On the line from where a worker is to his next stop (the first leg of a trip, or for a run that is full the way home after his last pickup), slow darker waves move in the direction of the arrow, so you can see at a glance where everybody is heading (they run only while the Trip Planner is on screen; the live web view has them too). Distances between stations are calculated from the real 3D positions of the stations (Star Citizen Wiki API) and match the distances read in the game.
- **Team status line.** Under the map is a small line of text that changes every ten seconds or so (the web page has the same line under its map, with the same text). What just happened comes first and is shown at once: *zzatvo is traveling towards Rat's Nest*, *zzatvo arrived at Rat's Nest*, *zzoega is loading Carbon at Starlight*, *zzatvo delivered Waste to Rat's Nest (187 SCU)*, *zzoega handed in 3 missions after 22m 41s*, *zzatvo sent zzoega 125,000 aUEC*, *zzoega died*. In between come the clock of the run a worker is flying (*bileh has spent 23m 12s on this trip*, it counts on while it is shown), stats of the session (runs, missions, average run time, Gm flown, fastest and longest run, quantum jumps and time spent in quantum travel, the ship somebody flies, the death count) and some fun. It only knows what the logs show: the quantum travel, the deaths and the money lines come from the Game.log of the player himself, so a member whose log is not read (not added, or the other computer is offline) is only in the lines that come from the runs. The game no longer writes kill lines, so a death is recognised by the burst of item recovery lines the game writes for the body of the player (shown a few seconds after the death). The destinations of Gaslight and Endgame are guessed from the pattern of the other names; if one is not right the line just says the worker picked a new destination.
- The plan ignores who is assigned to a location now. A location can be split over several trips and several workers: take what fits and fill the last seats with a small pickup that is close by, or come back for the rest.
- The plan is the one where the longest worker total is as short as possible, with a smaller weight on the combined Gm. It tries many ways of dividing the batches, and the suggestion is always the same for the same situation. It follows the batches you pick up while the tab is open.
- It uses the Pyro distance table and map positions, so a location that is not in it is left out and named under the summary. Only batches that are not picked up yet are planned.

## Leaderboards

The **Session Leaderboard** has one row per worker who started a cargo run in the session, and a total row, the highest earner on top (marked with a star on each side of the name and a gold row; the other names are indented to line up):
- **Avg Batches/Run** and **Avg Run Time**: averages over the completed runs (ended by a hand-in, not marked as failed). Batches/run counts the batches picked up at each location, like the Batches column of the run board.
- **Distance Travelled**: the distance in Gm flown in the worker's completed runs. A run counts Ruin to the first pickup, between the pickups in the order they were made, and back to Ruin. The distances are a fixed table for the Pyro stations (`Distances.cs`: positions from a Pyro map, Ruin legs read in the game). A pickup location the table does not know (a station you named differently, or one that is not in the table) is skipped. Sessions saved before this column existed get their distance filled in when you open them. **Gm / Hour** is that distance divided by the session duration (the same hours as Run Value / Hour).
- **Completed Runs** and **Perfect Runs** (completed runs with lost cargo None).
- **Delivered Batches**: the batches of the worker's finished runs. Nothing counts (also not the earned aUEC) until the run is done.
- **Total Run Value**: the value of the batches in the worker's finished runs (reward / stops of each mission), counted as soon as the run is done. Run counts (Completed Runs, Perfect Runs, Delivered Batches) also count at once; a perfect run stays perfect whatever happens to the server afterwards.
- **Total Earned aUEC**: the part of the run value whose mission is completed. **Lost Value**: run value minus earned, shown once the session has been quiet for 6 hours (until then the rest is just queued). Failed or abandoned missions never pay. **Run Value/Hour** is the run value divided by the session duration, **Share of Run Value** is his part of the total run value. The History leaderboard has the same columns over all saved sessions.
- The clocks only run while you have a contract that is not completed: **Session Time**, the per-hour numbers that use it, and the **Time** of a run that is still on the way stop as soon as everything is completed (the session time freezes at the last activity).
- **Start Session / Stop Session** (top right, level with the Options menu) is one button. Press **Start Session** (for example every morning), confirm with **Are you sure**, and the program reads the logs only from that moment until you press the same button again (now **Stop Session**, also with a confirmation). It can go on over several days, and the start is remembered when you close the program. Missions count for the session that was running when they ended; a mission that is still going belongs to the running session, unless it is old: a mission the log never saw end and that showed no sign of life for more than 3 hours before the session started (the game crashed, the other account stopped playing) is left out. The session clock does not count a stretch of an hour or more with no activity (the nights, or you walked away); it only stops counting, the session itself goes on.
- **Party** (the table at the very top right of the Session tab, with the name box and the Add / Remove buttons right under it; the small contracts and times tables are under it): type a name and press **Add** (or Enter) to put someone in the party, click a name and press **Remove** to take him out. **Active** is ticked while he is in the party: the program quietly saves the time each time you tick or untick someone, and the debts use it to split every payout between the people who were in the party at that moment. **Batches** is how many batches his ship holds, **Ship** is the ship he flies (a list of the hauling ships of the game data with the SCU each holds, for example C2 Hercules Starlifter 696 SCU + 128 off grid: the C2 and the Hermes have room for containers off the cargo grid, and that counts too; the SCU is for the cargo that goes out from Ruin, it does not change Batches) and **QT Drive** is the quantum drive in his ship (the Trip Planner uses Batches and QT Drive). **Color** is the colour of that worker on the Trip Planner Overview: click the square to pick another one (zzoega starts orange and zzatvo green).
- **Debts follow the party in time.** When a mission pays out, its reward is split equally between whoever was active in the party at that moment, and everybody is owed the value of the batches he carried. So if Bileh joins, flies two runs and no mission pays out while he is in the party, you owe him for his runs. If a payout comes while he is there, his share of it is already counted as paid to him. Missions that paid out before this table started tracking times keep the old split (the whole session party); a **Session Party…** typed in the Debts tab still overrides everything for that session.
- The two boards on the left only show **active missions** (not completed yet). **Hauling Tracker** lists the pickup locations with cargo still to deliver; when every batch of a location is handed in, the location moves to **Finished Stops** below it (shown when there is something in it). When a mission is completed it leaves both boards. **Cargo Runs** at the bottom keeps every run since the session started, so it is the log.
- The start/end table shows **Session Time** (ticks every second while you watch live), **Batches Delivered** (finished runs / all batches), **Active Missions** (accepted, not completed yet), **Missions Completed** (exactly the number completed in the session), **Total aUEC Earned** (what completed missions actually paid) and **aUEC/Hour** (earned per session hour).

The **History** tab has the same table for **all saved sessions** (with an extra Sessions column). Under it a line shows the best session (most revenue) and the best aUEC/hour. It adds up what each session saved, so it keeps working after the logs are gone. Sessions saved by an older version have earnings but no run counts until their logs are opened once.

## Debts tab

- **Earnings:** every session saves how much each worker carried (the Value of the locations assigned to him). The table shows this session, all sessions and the net balance per worker.
- **Split:** the reward of a session is split equally between everybody in the party, but each one is owed the value he carried. So somebody who carried nothing owes his whole share to the others, and somebody who carried more than his share is owed the difference. Lost cargo changes nothing.
- **Session Party…:** by default the party of a session is everyone who carried something. Use this button to add someone who was in the party but carried nothing (or to remove someone).
- **Balance:** pick a party member and see the balance with each other member. + means they owe the selected member, − means the selected member owes them. Type over a number to correct it, your correction is kept.
- **Money transfers:** `You sent <name>: <amount> aUEC` and `<name> has sent you: <amount> aUEC` are read from the logs (a transfer seen in both accounts' logs counts once). The list shows the transfers of the selected member. Tick **Payment** on the ones that pay off a debt, other transfers (like buying a ship) are ignored.
- On the Debts tab the **Balances** and the **Earnings** tables are side by side, under them are the **Money Transfers** (left) and the **Mission Payouts** (right). Mission Payouts lists every finished mission, newest first: when it completed, its payout, the party members who were active at that moment and shared it, and how much each of them got. The list is saved in the data file, so it stays after the logs are gone. The **Payout** box can be typed in: a mission that was handed in short pays less than its contract, so type what it really paid (it turns gold); the shares, the *Each* column and the debts then follow that amount, spread over the batches that were carried. Empty the box to use the reward of the contract again. A positive sum (somebody owes the selected member) is green and a negative one (he owes them) is red, in Balance and in Net Balance. The Meaning has the colour of its Balance.
- Balances add up over all saved sessions, so earlier money you settled by hand can be fixed with the typed corrections.

## Live Web View (let somebody watch)

**Options → Live Web View** switches on a small read-only web server inside the program. It shows all the tabs (Session, Trip Planner with its map and pages, Debts and History) with buttons on the page to switch between them, in the colours of your theme, and refreshes every few seconds (the running clocks, the session time and the run time of runs on the way, count up on the page every second in between). The page has the program icon as its icon (also in a bookmark). It only listens on your own computer (`http://localhost:8765`), and it can only show things: there is nothing to click or change, all changes are made in the program. The setting is remembered.
- To let somebody else watch, point a Cloudflare tunnel at `http://localhost:8765` on the same computer. Quick and free, no account: install `cloudflared` (`winget install Cloudflare.cloudflared`) and run `cloudflared tunnel --url http://localhost:8765`; it prints an `https://...trycloudflare.com` address that changes every time. For a fixed address, make a tunnel in the Cloudflare dashboard (Networking, Tunnels) with a published application for your own domain and the service URL `http://localhost:8765`; its connector runs as a Windows service. Anybody with the address can look, so share it only with people you trust.
- The program (with the web view on) and the tunnel connector have to be running on the same computer for the page to work.

## ScApiTool (Star Citizen Wiki API)

A separate small program, `ScApiTool.exe` (in the same Releases download, `ScApiTool.zip`). It asks the [Star Citizen Wiki API](https://api.star-citizen.wiki) for game data (locations, missions, commodities, ships, items, and the API's own list of addresses) and saves the raw answers as `.json` files in a `ScApiData` folder next to it, with a `summary.txt` and a zip of everything.
- Double-click it with no arguments for the standard set. `--all` removes the page limit. Give it an address like `ScApiTool.exe /api/missions` to download anything else the API has.
- **UEX** (uexcorp.space): create an app on the UEX site (My Apps) and copy its access token. Put the token alone on the first line of a file called `uex-token.txt` next to `ScApiTool.exe` (or set the environment variable `UEX_TOKEN`). The tool then also downloads the UEX places, terminals, commodities and prices, saved as `uex-....json`. `ScApiTool.exe --uex` does only UEX, `ScApiTool.exe uex:/terminals` any other UEX address. The token is a secret: it is sent only to the UEX site and is never written to the results, so the zip is safe to hand over. Never put the token in the repository.
- Pages are asked for by number, so a list is never downloaded twice (the API's own "next" link repeated a page and filled the mission list with the same 270 missions).
- The data comes from fan sites that are not affiliated with Cloud Imperium Games. Credit api.star-citizen.wiki and uexcorp.space if you publish anything made from it.

**Gateways.** The Nyx and Stanton Gateway have exactly the same position in the log, so the program tells them apart by the order of their location ids once both have been seen. It now also uses what the game says itself: when you plan a quantum route a few minutes after picking something up at a gateway, the log says *Projected Start Location is Stanton Gateway*, and that names the gateway you were at (and, when only one of the two was seen, the other one is the other gateway). It only works when a quantum route is planned from the gateway; otherwise the gateway stays *Unknown* until both have been seen, and you can still type its name in the Stops board.
